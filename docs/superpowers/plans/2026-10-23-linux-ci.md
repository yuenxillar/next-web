# Linux CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Get the `next-web-retry` crate verified on Linux by GitHub Actions, so the green check is the evidence that the crate is production-ready on a machine other than the Windows development box.

**Architecture:** One path-filtered workflow with three jobs: a fast required `retry` job (format, clippy, tests, docs), a required `consumers` job that builds the crates depending on `retry`, and an informational `deny` job. Pull requests always run the workflow (no path filter on `pull_request`) so a required check can never stay pending.

**Tech Stack:** GitHub Actions, `dtolnay/rust-toolchain`, `Swatinem/rust-cache`, `taiki-e/install-action`, `cargo` (fmt, clippy, test, doc, check), `cargo-deny`.

**Spec:** `next-web-retry/README.md` (section "Testing") plus the readiness criteria agreed in this session: Linux CI green once, and a metrics integration seam with an exporter.

## Global Constraints

- Repository: `https://github.com/yuenxillar/next-web`, default workflow directory `.github/workflows/` (currently absent — this plan creates it).
- Declared toolchain floor: `rust-version = "1.98.1"` in the workspace `Cargo.toml`; edition 2024.
- `Cargo.lock` is committed; every cargo command in CI uses `--locked`.
- Workspace-wide clippy/rustfmt are **not** clean today (`cargo fmt --all --check` fails in `next-web-ai`, `next-web-core` emits 75 clippy warnings). CI therefore gates only the crates this work owns, and states that limitation in the docs task.
- No secrets, no publishing, no cache beyond `Swatinem/rust-cache`.
- The dev machine is Windows; every command must be proven locally before it is trusted in CI.

## Review Focus

- **A pull request that does not touch `next-web-retry`** must still report the required check. A `pull_request` path filter would leave the check pending forever and block the PR, so the workflow triggers on every PR and stays fast instead.
- **A fork PR** runs with a read-only token: no secret, no write permission, no `gh` call may be required for the job to pass.
- **The toolchain floor**: if the runner's `stable` is older than 1.98.1, cargo aborts with "package requires rustc 1.98.1". The job must show that error clearly and the fix is a one-line channel pin, not a code change.
- **A lockfile drift** (a dependency added without committing `Cargo.lock`) must fail the `--locked` build with the standard cargo message, not silently resolve a new graph.
- **A skipped workflow**: `workflow_dispatch` must be available so the check can be re-run without an empty commit.

### Task 1: The `retry` workflow

**Files:**
- Create: `.github/workflows/retry.yml`
- Test: the local command run in Step 2 (there is no unit-testable artifact for YAML; the local exit codes are the test, the first CI run is the acceptance).

**Interfaces:**
- Consumes: nothing.
- Produces: the check names `retry (linux)` and `consumers (linux)` (used by Task 2) and the workflow name `retry` (used by `gh run list --workflow retry.yml`).

- [ ] **Step 1: Prove the required commands pass locally**

Run, from the repository root:

```powershell
cargo fmt -p next-web-retry --check
cargo clippy -p next-web-retry --all-targets --locked -- -D warnings
cargo test -p next-web-retry --locked
$env:RUSTDOCFLAGS="-D warnings"; cargo doc -p next-web-retry --no-deps --locked
cargo check -p next-web --features enable-retry --locked
cargo check -p next-web-ai --locked
```

Expected: every command exits 0. If one does not, stop and fix the crate before writing the workflow; a workflow that codifies a failing command is worse than none.

- [ ] **Step 2: Write the workflow**

Create `.github/workflows/retry.yml`:

```yaml
name: retry

on:
  push:
    branches: ["**"]
    paths:
      - "next-web-retry/**"
      - "next-web/**"
      - "next-web-ai/**"
      - "Cargo.toml"
      - "Cargo.lock"
      - ".github/workflows/retry.yml"
  pull_request:
  workflow_dispatch:

concurrency:
  group: retry-${{ github.ref }}
  cancel-in-progress: true

env:
  CARGO_TERM_COLOR: always
  RUST_BACKTRACE: 1

jobs:
  retry:
    name: retry (linux)
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
        with:
          components: rustfmt, clippy
      - uses: Swatinem/rust-cache@v2
      - name: Toolchain
        run: rustc -vV && cargo -vV
      - name: Format
        run: cargo fmt -p next-web-retry --check
      - name: Clippy
        run: cargo clippy -p next-web-retry --all-targets --locked -- -D warnings
      - name: Test
        run: cargo test -p next-web-retry --locked
      - name: Docs
        run: RUSTDOCFLAGS="-D warnings" cargo doc -p next-web-retry --no-deps --locked

  consumers:
    name: consumers (linux)
    runs-on: ubuntu-latest
    timeout-minutes: 30
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - uses: Swatinem/rust-cache@v2
      - name: The facade feature
        run: cargo check -p next-web --features enable-retry --locked
      - name: The AI crate
        run: cargo check -p next-web-ai --locked

  deny:
    name: deny (informational)
    runs-on: ubuntu-latest
    continue-on-error: true
    timeout-minutes: 10
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - uses: taiki-e/install-action@cargo-deny
      - name: Policy check
        run: cargo deny --manifest-path next-web-retry/Cargo.toml check advisories bans licenses sources
```

- [ ] **Step 3: Validate the YAML locally if a linter is available**

Run:

```powershell
actionlint -version
```

If it prints a version, run `actionlint` and expect exit 0. If it reports "not recognized", skip this step: GitHub validates the file on the first push, and Step 5 is the real acceptance.

- [ ] **Step 4: Commit**

```powershell
git add .github/workflows/retry.yml
git commit -m "build(ci): verify next-web-retry on linux"
```

- [ ] **Step 5: Push and confirm the first green run**

```powershell
git push
gh run list --workflow retry.yml --limit 1
gh run watch
```

If `gh` is not installed or not authenticated, push and watch the run in the repository's Actions
tab instead; the acceptance is the same: the `retry (linux)` and `consumers (linux)` checks
conclude green.

Expected: the newest run concludes `success` and both `retry (linux)` and `consumers (linux)` are green. If the run fails with `package requires rustc 1.98.1`, change the `retry` and `consumers` toolchain steps to `dtolnay/rust-toolchain@1.98.1` and push again; if it fails on a command that passed locally, the failure is Linux-specific and is a finding, not a flake — fix the crate.

- [ ] **Step 6: Verify the failure path is honest**

Temporarily break formatting on one line of `next-web-retry/src/lib.rs` (add two spaces), push to a scratch branch, and expect the `retry (linux)` job to fail at the `Format` step. Revert the change with `git checkout -- next-web-retry/src/lib.rs` and push the revert. This proves the gate actually gates.

```markdown
## Continuous integration

Every pull request runs `.github/workflows/retry.yml`, which gates this crate on Linux:

| Check | Command |
|-------|---------|
| Format | `cargo fmt -p next-web-retry --check` |
| Clippy | `cargo clippy -p next-web-retry --all-targets --locked -- -D warnings` |
| Test | `cargo test -p next-web-retry --locked` |
| Docs | `RUSTDOCFLAGS="-D warnings" cargo doc -p next-web-retry --no-deps` |
| Consumers | `cargo check -p next-web --features enable-retry`, `cargo check -p next-web-ai` |

The workflow runs on every pull request without a path filter, so the required checks always
report. Pushes are path-filtered to the crates listed in the workflow to avoid rebuilding this
crate for unrelated changes.

Workspace-wide `clippy` and `rustfmt` are not enforced yet: `cargo fmt --all --check` and
`cargo clippy --workspace` still report pre-existing findings in `next-web-core` and
`next-web-ai`. Widening the gate is a follow-up, and this section must be updated when it happens.
```

## Amendments made during execution

- The toolchain is pinned explicitly: dtolnay/rust-toolchain@stable with
  	oolchain: "1.98.1", matching the workspace ust-version. The local machine already runs
  rustc 1.98.1, so the pin is reproducible rather than aspirational; if GitHub cannot download that
  version the job fails with a rustup error, which is the intended signal.
- The clippy step gained --no-deps. Without it, -D warnings also applies to the workspace path
  dependencies, and 
ext-web-context alone has 16 pre-existing clippy findings, so the gate failed
  before it inspected this crate. Verified locally: with --no-deps the step exits 0, without it
  the step exits non-zero on 
ext-web-context.
- The consumers job also checks the etry_metrics example bin, which the metrics plan added.
- The deny job runs at the workspace root (cargo deny check advisories bans licenses sources)
  and stays informational; it reports the whole workspace against deny.toml, and cargo-deny
  has no per-manifest invocation in the form the original task assumed.
- --locked was removed from every CI command. The Global Constraints assumed "Cargo.lock is
  committed"; it is not (.gitignore:10 ignores it and git ls-files does not know it). A CI
  checkout therefore has no lock file, and every --locked command failed during resolution — the
  first run failed at Clippy and The facade feature after 1-2 seconds with exit 101, and deny
  with exit 7, while Format passed because it resolves nothing. The jobs now resolve the graph
  from the manifests (cargo's MSRV-aware resolver keeps it compatible with 1.98.1). Committing
  Cargo.lock and restoring --locked is the reproducibility upgrade, and the README states that.
