📋 WHAT WAS IMPLEMENTED

This implementation provides a complete SockJS configuration API for Next Web
WebSocket, matching Spring Framework's design. SockJS enables WebSocket
emulation with automatic fallback to HTTP transports when WebSocket is
unavailable (legacy browsers, corporate proxies, network restrictions).

📚 API EXAMPLE

use next_web_websocket::config::{WebSocketConfigurer, WebSocketHandlerRegistry};
use std::sync::Arc;

#[derive(Clone)]
struct MyConfig;

impl WebSocketConfigurer for MyConfig {
    fn register_websocket_handlers(
        &mut self,
        _ctx: &mut dyn ApplicationContext,
        registry: &mut dyn WebSocketHandlerRegistry,
    ) {
        registry
            .add_handler(Arc::new(MyHandler), vec!["/ws".to_string()])
            .with_sock_js()
            .set_heartbeat_time(25_000)
            .set_disconnect_delay(5_000)
            .set_stream_bytes_limit(128 * 1024)
            .set_websocket_enabled(true)
            .set_allowed_origins(vec!["https://example.com".to_string()]);
    }
}

🔄 SOCKJS FALLBACK MECHANISM

SockJS provides automatic fallback when WebSocket is unavailable:

  Priority 1: WebSocket (native)
    ↓ (if unavailable)
  Priority 2: XHR Streaming (HTTP long-lived connection)
    ↓ (if unavailable)
  Priority 3: XHR Polling (traditional HTTP polling)

Frame Protocol:
  • 'o' - Open frame (connection established)
  • 'h' - Heartbeat frame (keep-alive every 25s)
  • 'a["msg1","msg2"]' - Message array frame (JSON-encoded)
  • 'c[code,"reason"]' - Close frame (session termination)
